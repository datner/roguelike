# Plan: balance bench

Handoff document. Read ADR 0005 (determinism), ADR 0006 (time), ADR 0017 (skills), ADR 0024
(techniques) and `game/CLAUDE.md` first.

## Goal

A way to see whether a build is obviously out of line. A **build** (skills, stats, gear, what it knows,
the style it follows, how it fights) is set in front of **training dolls** for a fixed window of ticks,
over many seeds, and the bench reports what it dealt next to what it cost: how hard the build is to
reach, what it needs to find, and how much it spends doing it. Numbers alone mislead (a build that does
twice the damage may need ten times the XP); the report puts them side by side so an outlier stands out
in its context. It is a tool for the owner and for agents changing content, not part of the game.

## Decisions taken for this plan

- **The simulation lives in `game`, the program outside it.** `game/src/balance.rs` turns a build and
  a scenario into a report through the real systems (`GameState`, `take_turn`, commands, events), so it
  measures the game, not a model of it. A new workspace crate `bench` (a binary, depends on `game`
  only) reads the files, runs, and prints. `game` still does no I/O beyond loading data.
- **Builds and scenarios are data**, in `bench/builds/*.ron` and `bench/scenarios.ron`, not in `data/`:
  they are not game content. A build names a base blueprint (`Player`), skill levels, stats, equipment
  by blueprint, techniques and spells known, the style followed, and a **policy**.
- **A policy is a priority list**, re-read every turn: `Perform(technique)`, `Cast(spell)`, `Fire`,
  `Bump`, each taken when ready and a doll is in reach, else the next. It drives the same
  `PlayerAction`s the keyboard does, so a refusal costs nothing and falls through. Smarter play (kiting,
  combos by intent) is out of scope; a combo is its steps listed in order.
- **The build does not learn during a run.** `Learner` is removed from the build's creature, so the
  window measures one fixed build, not one that levels as it goes.
- **Dolls are creatures that never act and never die**: a blueprint with no `Speed` (the scheduler never
  gives it a turn), huge health, and variants for what changes a blow: `Doll` (bare), `ArmoredDoll`
  (armor like a castle guard's), `NimbleDoll` (a Dodge skill, for hit chance and grazes). They live in
  `data/entities/` as ordinary blueprints, since the vision's "sparring a dummy" practice can use them
  later. Damage is read from their lost health.
- **Two windows, both in ticks.** **Burst: 1000 ticks** (10 standard turns): what a fresh build does
  at the start of a fight, with everything off recharge and full pools. **Sustained: 10000 ticks**
  (100 turns): recharges, pools and ammunition come into it. Both are reported per 100 ticks (per
  standard turn), so they compare directly.
- **Many seeds, a spread, not one number.** Each scenario runs on 50 seeds (`0..50`); the report gives
  the mean and the 10th and 90th percentiles. Same builds, same data, same report (ADR 0005).
- **Cost is computed from data, not judged by hand:**
  - **XP to build**: the sum of `skill::xp_for` over the build's skill levels, and the levels of the
    style it follows. The headline "how hard to reach".
  - **What it needs**: each item, technique, spell and style, with where it comes from, read from the
    data: the starting kit, a dungeon's finds (dungeon, floors, phases), a manual, a discovery (and its
    requirements), a style's invention (and at what level).
  - **What it spends**, measured during the run: mana, health (blood casting), stamina, arrows shot and
    broken, and the tick a pool or the quiver first ran dry, if it did.
- **Outliers are flagged, not judged.** Builds are compared to each other: damage per turn divided by
  XP to build, and the report marks any build more than 1.5× the median of that ratio, or any build
  whose resources run dry inside the burst window. The owner decides whether a flag is a problem.
- **The report is checked in.** `bench/report.md`, regenerated by `scripts/balance.sh` and compared by
  `scripts/balance.sh --check` (like `shots.sh`), so a content change that moves balance shows as a
  diff in review. Not part of `check.sh`: it is slower and a balance shift is not an error.

## Slices

Each slice ends with `scripts/check.sh` green and a commit, and is marked done here first.

### 1. A doll, a build, a number — done
- `data/entities/Doll.ron`, `ArmoredDoll.ron`, `NimbleDoll.ron`.
- `game/src/balance.rs`: `Build` (base, skills, stats, equipment, policy with `Bump` only for now),
  `Scenario { dolls: Vec<(blueprint, (dx, dy))>, window: u64 }`, `run(blueprints, &Build, &Scenario,
  seed) -> Run` on a hand-built open arena (no generator, ADR 0009 untouched), and `Run { dealt, hits,
  grazes, misses }`.
- `bench` crate: loads `bench/builds/*.ron`, runs burst and sustained against one doll of each kind over
  the seeds, prints a table. First builds: the starting character, a rapier fencer, a sabre user.
- `scripts/balance.sh` runs it; README "Structure" lists `bench/`; `scripts/map.sh` covers the crate.
- Tests (in `game`): a doll never acts and never dies; a run is the same per seed; the build does not
  gain XP; the fencer deals more to a bare doll than to an armored one.

### 2. Policies: techniques, spells, shots, areas — done
- Policy entries `Perform`, `Cast`, `Fire`; dolls placed at range for shots and spells, in a pack of
  three for cleaves and novas (scenarios name which).
- Builds: an archer (short bow, quiver), a cleaver (sabre, cleave), a tri-sword form, a mana caster,
  a blood caster, a brawler.
- Tests: a policy falls through a recharging technique to a bump; an area technique counts every doll
  it hits; a shot with no arrows falls through to a bump.
- As built: no blood caster. Blood casting is a discipline part on the caster (`BloodCasting`), which a
  build cannot add; it waits for a build field for extra parts. A pyromancer (cooldowns) and a fencing
  lunger (a style and a technique) joined instead. Every build runs every scenario.

### 3. What it spends — done
- `Run` gains mana, health and stamina spent, arrows shot and broken, and the first tick each ran dry.
- Report columns for them; the burst-dry flag.
- Tests: a caster's mana spent matches its casts; an archer runs dry of arrows in the sustained window
  with a small quiver and falls back to bumping.
- As built: a pool's spend is read from the pool itself (what it held when the action was taken, less
  what it holds after), so no counter is added to the game. "Dry" is judged after the run against
  the cheapest price paid in the whole run, so a caster is not called dry for want of a big spell it
  stops casting. The spending table covers the first scenario only. Arrows are never picked up.

### 4. What it costs — done
- `balance::cost(blueprints, &Build) -> Cost`: XP to build, and the sources of each thing it needs, read
  from the starting kit, dungeon spawn lists, `Teaches`, discoveries and `Style.invents`.
- Report: XP to build, sources, damage per turn per 1000 XP, the outlier flag.
- Tests: XP to build sums the curve; a manual's technique names the manual and its dungeon; a
  discovery's style lists its requirements.
- As built: items are not listed per dungeon (every item blueprint can lie about anywhere), so an
  item's source says how rare it is ("1 in 17 finds") and which dungeon creatures wear it. XP to build
  depends only on levels, so for now it mostly counts how many skills a build leans on; the skill
  weights are not in it.

### 5. The checked-in report
- `bench/report.md` written by `scripts/balance.sh`; `--check` regenerates to a scratch file and diffs.
- `game/CLAUDE.md`: a rule line for `balance.rs`; root `CLAUDE.md` commands: when to run the bench
  (after changing numbers in content, combat or skills).
- Tests: `bench` formats a fixed `Run` into the expected table (the report's shape is pinned without
  running the slow bench).

### 6. A report to read (nice to have)
- `bench` also writes `bench/report.json`: every number the table has, plus the per-seed spread, so
  anything can draw it. The markdown table stays the checked-in, diffable record.
- A page template, `bench/page.html`: self-contained, reading the JSON embedded in it at generation.
  Damage per turn against XP to build (one point per build, outliers marked), burst against sustained
  per build, a timeline of when each resource ran dry, the cost sources as a list per build, and what
  moved since the committed report.
- A project skill, `/balance-report`: runs `scripts/balance.sh`, fills the page, publishes it as a
  private artifact, and adds a short written reading on top (what stands out, what moved and why it
  likely did, given the recent commits). The numbers come from the bench; only the reading is written
  by the agent.
- Tests: the JSON round-trips; the page builds from a fixed report without errors.

- Enemies that fight back, survivability, and damage taken: dolls only measure offence. A "how long
  does this build last against a goblin pack" bench is a later plan.
- Tuning anything: the bench reports, the owner decides.
- Movement, kiting and positioning in policies; combos beyond listed steps.
- Running in CI or `check.sh`.

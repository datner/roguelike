# Code map

Generated by `scripts/map.sh`; do not edit. One line per module: path (size, rounded to 100 lines) — its `//!` summary. Signatures: `scripts/map.sh --sigs <file or dir>...` (nested = inside the `impl` or `mod` above; test modules skipped).

## game

- `game/src/ai.rs` (~400) — Non-player decisions. AI only chooses a `Command`; the scheduler queues it like any other action, so moving and bump-attacking reuse `TryMove`.
- `game/src/aim.rs` (~500) — Aiming, for frontends (ADR 0013): which tiles are worth targeting and what a shot at one would do, in plain data. Computed with the same functions the commands use, so the preview cannot disagree with the shot.
- `game/src/ammo.rs` (~400) — Ammunition handling (ADR 0013): which launcher is wielded, nocking an arrow, and the quiver. A nocked arrow is the only thing in its launcher's `Inventory`; a quiver's arrows are its `Inventory`, so both stay inert and are saved and despawned with their holder.
- `game/src/area.rs` (~200) — Which tiles a spell's `Shape` covers (ADR 0014): pure functions of the map, the caster's tile and the aimed tile, so a cast and its preview cover the same ground. Walls block. Tiles come nearest the centre first (ties by row, then column), which is also the order an area is animated in.
- `game/src/blueprint.rs` (~1400) — Data-driven entity definitions, loaded from `data/entities/*.ron`. A blueprint's name is its file stem. Inheritance is resolved once at load time, so spawning never walks the parent chain.
- `game/src/camera.rs` (~100) — Which part of the zone a viewport shows (ADR 0009). The only place that converts between screen tiles and world tiles.
- `game/src/cell.rs` (~100) — The rendering seam's output (ADR 0001): one glyph and its colours per screen cell.
- `game/src/combat.rs` (~1200) — Combat events and handlers, plus the shared rolls used by both the real command applier and the side-effect-free `preview_damage`.
- `game/src/command.rs` (~1000) — `Command` and `apply_commands`: the only place the world is mutated during play (ADR 0002).
- `game/src/cost.rs` (~100) — Every action's energy cost, in one place so relative costs are reviewable. See ADR 0006 for the energy model.
- `game/src/discovery.rs` (~300) — Discovery (ADR 0018): combinations of skills that, once reached, inspire the learner with something new. Listed in `data/discoveries.ron`; checked only after a use with stakes, so practice never inspires.
- `game/src/effect.rs` (~500) — Timed effects (ADR 0006): entities attached to a target, carrying `Timed { start, duration }`. Whether an effect is active is always read from those timestamps; timers only perform end-of-effect side effects and periodic ticks, and each one re-checks the timestamps before acting.
- `game/src/entity.rs` (~800) — Components: plain data stored in the hecs world. Behaviour lives in event handlers (see `event`) and in the command applier, never here.
- `game/src/equipment.rs` (~300) — Equipping items on body parts (Qud-style anatomy). An equipped item is in its owner's `Attachments` with `EquippedOn(part)`, so its parts take part in the owner's events; a carried one is in `Inventory` and inert.
- `game/src/event.rs` (~300) — Synchronous, typed event dispatch.
- `game/src/explore.rs` (~400) — Auto-explore: the player's next step toward an unfound floor item, then unexplored ground, then the exit, judged only from what the player knows.
- `game/src/fov.rs` (~300) — The player's field of view: Albert Ford's symmetric shadowcasting (ADR 0007). Symmetry — A sees B iff B sees A, between floor tiles — is what lets `ai::can_see_player` reuse the player's view instead of computing one per actor.
- `game/src/grammar.rs` (~200) — Log-message grammar: every sentence about an entity goes through a `Subject`, so the player reads "You take 3 damage." and everyone else "The goblin takes 3 damage."
- `game/src/holding.rs` (~100) — Who holds what: the owner-side lists `Attachments` (in use, so its parts fire) and `Inventory` (carried, inert). Every change to either list goes through here, so how holding is stored can change in one place.
- `game/src/input.rs` (~100) — The rendering seam's input (ADR 0001): frontends translate raw keys into `InputEvent`.
- `game/src/lib.rs` (~100) — Simulation and game logic. This crate must never depend on a terminal/graphics crate (crossterm, ratatui, etc.) — that boundary is what makes the rendering seam real instead of aspirational.
- `game/src/lore.rs` (~300) — Lore (ADR 0017): what the player knows about the creatures they meet. Beast lore grows by novelty, the first sight of each kind of creature, and decides how much the look cursor reveals (`inspect`); Arcana grows by the first cast of each spell and reads the spells a creature knows.
- `game/src/map.rs` (~200) — Tiles, the generic `Grid<T>` (out-of-bounds reads are `None`), and spawn placement.
- `game/src/prio.rs` (~100) — Every event-handler priority in the game. Lower values run first. Keeping them in one place makes the relative ordering reviewable. Priorities must be unique per event type (`EventRegistry::on` panics otherwise); they may repeat across different events.
- `game/src/ranged.rs` (~900) — Flight of a thrown or fired thing (ADR 0013): the straight line it travels, the first creature on it, and where it comes to rest. No RNG: an attack always hits whoever is first in line.
- `game/src/rng.rs` (~100) — Per-subsystem RNG streams (ADR 0005). Each subsystem draws only from its own `Pcg64` stream, so extra draws in one subsystem never shift another's results. Streams about a place (map, spawn) come from its zone seed (ADR 0009); the rest from the world seed.
- `game/src/save.rs` (~1600) — Save games (ADR 0008): `GameState` to and from a RON string. File IO is the frontend's job; this module only converts.
- `game/src/side.rs` (~100) — Who fights whom (ADR 0015). Until there are factions there are two sides: hostile creatures and the player's. A summon is on its owner's side, so a goblin shaman's summons are hostile and the player's fight for them.
- `game/src/skill.rs` (~800) — Skills (ADR 0017): how well a creature does what it does, grown by doing it. Skills are flat, overlapping tags listed in `data/skills.ron`; one action uses several at once, and its level is their weighted average. Only XP is stored; levels are derived, so the curve can change freely.
- `game/src/spawn.rs` (~100) — `Spawn`: what to create and where it goes, handed to `GameState::spawn`, the only way entities are made (ADR 0008). Placement and holding are described here once instead of patched on after each spawn.
- `game/src/spell.rs` (~2300) — Spells (ADR 0014): what makes a cast possible and what it costs lives in the caster's disciplines, what it does lives in the spell. A cast fires `CheckCast` and `PayCost` at the caster, so a discipline is a part with handlers and `cast` never learns which resources exist.
- `game/src/state.rs` (~1000) — `GameState`, the message log, and `render_view`, which turns what the player knows into a `Grid<Cell>`.
- `game/src/style.rs` (~400) — Styles (ADR 0019): practices a creature discovers and follows. A style grows by uses that follow it; its principles switch on at levels of its skill, so a fresh style changes nothing. Known styles are carried and inert; the followed one is attached.
- `game/src/testkit.rs` (~200) — Test-only additions to `spawn::Spawn`. Tests describe an ad-hoc entity by what it is (`.item()`, `.armor(2)`, `.equipped_on(owner, 2)`), so a change to how a component or a holding is stored is made here once, not in every test.
- `game/src/time.rs` (~600) — Game time (ADR 0006): the global `Tick` clock, the timer queue, and the energy scheduler that decides who acts next.
- `game/src/training.rs` (~200) — Training on purpose (ADR 0017): lessons, a big chunk of XP once per kind of thing, and practice, a little XP a turn up to a ceiling. Neither has stakes, so neither repeats familiarity, trains a style or inspires.
- `game/src/view.rs` (~500) — Read-only views of the player's state for frontends: plain data, no hecs types, so `term` can draw panels without touching the world.
- `game/src/zone.rs` (~400) — Zones (ADR 0009): fixed-size areas larger than the screen, each seeded from the world seed and its coordinates, and the cellular-automata cave generator that fills them.

## term

- `term/src/app.rs` (~700) — The title-menu session, and the blocking, turn-based game loop and panel layout.
- `term/src/input.rs` (~300) — Key bindings: the only place a `KeyEvent` becomes a `game::InputEvent`, `MenuInput` or `OverlayInput`.
- `term/src/main.rs` (~100) — Terminal frontend entry point: CLI args and wiring.
- `term/src/menu.rs` (~400) — Title menu: new game, continue, load, and save management (rename, delete).
- `term/src/overlay.rs` (~900) — The hovering panel: a modal box drawn over the map with an inventory and an equipment view, and the skills the player has learned. Pure state plus drawing; `app::run` feeds it keys and performs the actions it returns.
- `term/src/saves.rs` (~300) — Save files: one per character, listed and managed from the title menu, written on quit.
- `term/src/side_panel.rs` (~300) — The side column: a stack of panels to the right of the map, log and status. Each `Panel` supplies a title and lines; `draw` stacks them in `PANELS` order. Hidden on narrow terminals so the map keeps its room.
- `term/src/targeting.rs` (~500) — Throwing and casting from the keyboard: a small list to pick what to throw or cast, then a cursor to pick where. Pure state plus drawing, like `overlay`; `app::run` feeds it keys and takes the turn it returns. What a shot would do comes from `game::aim`, never worked out here.
- `term/src/tui.rs` (~100) — Terminal init and restore (raw mode, alternate screen, keyboard enhancement, panic hook).
- `term/src/widgets/map_widget.rs` (~100) — Draws the game's `Grid<Cell>` into a ratatui buffer.
- `term/src/widgets/mod.rs` (~100) — ratatui widgets for the game's output.
